# 设备代码同步方案（让分析基于最新代码）

> 目标：让本机（分析端）拿到设备上**此刻真实**的源码状态，且两边不再发散。
> 原则：**先固定基线，再传增量；能传 diff 就不传整棵树。**

---

## 零、先做一件事：在设备上固定基线（1 分钟）

无论后面走哪条路，这一步都要先做——否则我们对着一个随时会变的目录讨论，没有意义。

```bash
cd ~/OpenISAC            # 换成设备上的实际路径
git add -A
git commit -m "device snapshot $(date +%F_%H%M)" || echo "无改动"
git rev-parse --short HEAD          # 记下这个哈希
git status --porcelain              # 应为空；非空说明有未跟踪文件
```

以后所有对比都对着这个 commit，而不是对着一个活的目录。

---

## 一、三条路，按省事排序

### 路线 A：同一局域网 + 已开 SSH（最省事）

适合：设备和本机都在 `192.168.3.x`。

在本机执行（我会用同样的命令）：

```powershell
# 先探通不通
ssh 用户名@设备IP "echo ok && uname -a"

# 只传源码，排除构建产物（build/ 可能上百 MB）
scp -r 用户名@设备IP:~/OpenISAC/include  D:\isac\device_src\
scp -r 用户名@设备IP:~/OpenISAC/src      D:\isac\device_src\
scp -r 用户名@设备IP:~/OpenISAC/config   D:\isac\device_src\
scp -r 用户名@设备IP:~/OpenISAC/scripts  D:\isac\device_src\
scp    用户名@设备IP:~/OpenISAC/CMakeLists.txt D:\isac\device_src\
```

传完我直接读本地副本，并与 `D:\isac\OpenISAC_new` 逐文件比对。

> Linux 侧如果没有 `rsync`，用 `scp -r` 即可；有的话更好：
> `rsync -av --exclude build/ --exclude .git/ 用户@IP:~/OpenISAC/ /mnt/d/isac/device_src/`

### 路线 B：不在同一网段（跨网/跨城）

先用一条隧道把设备"放进"同一张网，再走路线 A：

| 方式 | 适用 | 备注 |
|---|---|---|
| **Tailscale**（推荐） | 两端都能装 | 装完 `tailscale ip` 拿到 100.x 地址，直接 ssh |
| **frp + 轻量 VPS** | 国内最稳 | 需一台 VPS 做中转 |
| **学校 VPN** | 设备在校内 | 断开后 IP 会变，注意 |

### 路线 C：完全没有网络互通（只能靠 U 盘/聊天传文件）

在设备上打一个**单文件包**，然后拷过来：

```bash
cd ~
git bundle create openisac_device.bundle --all
# 同时打一个未提交改动的补丁（保险）
cd ~/OpenISAC && git diff > /tmp/wip.diff
```

把 `openisac_device.bundle`（含全部历史，通常几十 MB）和 `wip.diff` 传到本机，我这边：

```powershell
git clone D:\isac\openisac_device.bundle D:\isac\OpenISAC_device
```

## 二、更省流量的做法：先传"指纹"，再传差异文件

如果只想传几百 KB，用这个顺序（推荐在设备未知、网络一般时使用）：

### 步骤 1：设备上生成指纹清单

```bash
cd ~/OpenISAC
find include src config scripts -type f \
  \( -name '*.hpp' -o -name '*.cpp' -o -name '*.yaml' -o -name '*.py' -o -name '*.h' \) \
  -exec sha256sum {} \; | sort -k2 > /tmp/manifest_device.txt
```

把这个文件（通常 20–50 KB）发过来。

### 步骤 2：我这边比对，告诉你哪些文件真的不一样

我会用同样的命令生成本机的清单，逐条比哈希，输出：

- **只有设备有**的文件（新增功能）
- **两边都有一致**的文件（不用传）
- **两边都有但不同**的文件（需要传，通常 5–20 个）

### 步骤 3：只传那十几个文件

```bash
scp 用户名@设备IP:~/OpenISAC/src/OFDMModulator.cpp D:\isac\device_src\src\
```

**总传输量常常不到 200 KB，但信息是完整的。**

---

## 三、传完之后我会做什么

1. 逐文件比对 `device_src` 与 `D:\isac\OpenISAC_new`，列出**真实差异清单**
2. 判断这些差异是否影响已有结论（例如：分帧逻辑改过没有、外码改过没有、队列参数改过没有）
3. 据此**重写** A 组改造方案里的行号与函数名（现在那份是设计草案，不是补丁）
4. 给你一份《设备代码现状说明》——包括：哪些是我此前分析过的、哪些是新增的

---

## 四、需要你告诉我的三件事

1. **设备是什么系统**（Ubuntu / Windows）
2. **设备现在在哪个网**（家里局域网 / 学校内网 / 完全离线）
3. **设备上有没有开 SSH**（`sudo systemctl status ssh` 看一眼）

有这三条，我就能给出唯一一条可执行的命令序列，而不是三个选项。

---

## 五、一条纪律

**在对齐之前，不要在设备上按我的方案改代码。**
现在那份《A 组分帧模式改造方案》是按 `OpenISAC_new` 写的设计稿，行号未必对得上。先对齐，再动手——否则两边都变脏，排查成本比收益高。
