## 二、LLR 怎么算出来：完整推导

### 2.1 起点：QPSK 星座图

发送的 QPSK 符号在复平面上只有 4 个可能位置：

```
        Q
        │
   ·    │    ·
 (-d,+d)│(+d,+d)      d = 1/√2 ≈ 0.707
────────┼──────── I
 (-d,-d)│(+d,-d)
   ·    │    ·
```

**每个点携带 2 个比特**：实部 $I$ 决定一个比特，虚部 $Q$ 决定另一个。

约定：$I = +d$ 表示比特 0，$I = -d$ 表示比特 1。

### 2.2 关键事实：接收端知道"偏了多少"

收到的是 $y = s + n$，$n$ 是噪声。

**接收端能算出 $y_I$ 的具体数值**，而这个数值比"猜一个 0 或 1"包含更多信息：

```
发送 I = +d (比特0)

   实际收到 y_I = 0.80   ← 偏了 0.093，但还在 I>0 这一侧
   实际收到 y_I = 0.05   ← 几乎贴在 0 线上，很不确定
   实际收到 y_I = -0.30  ← 跑到 I<0 那侧了，但只偏了一点
```

**若只输出 0/1（硬判决）**，三种情况都会被判成"0, 0, 1"，**丢掉了"有多确定"这一层**。

### 2.3 推导：max-log-MAP 怎么得到 LLR

定义：

$$\mathrm{LLR}(b)=\ln\frac{P(b=0\mid y_I)}{P(b=1\mid y_I)}$$

先验等概时，用贝叶斯定理可化简为似然比：

$$\mathrm{LLR}(b)=\ln\frac{P(y_I\mid b=0)}{P(y_I\mid b=1)}$$

噪声是高斯的：

$$P(y_I\mid b=0)=\frac{1}{\sqrt{\pi\sigma^2}}\exp\left(-\frac{(y_I-d)^2}{\sigma^2}\right)$$

> 指数里是 $\sigma^2$ 而不是 $2\sigma^2$：复噪声总方差 $\sigma^2$ 分到 I、Q 两维，每维方差 $\sigma^2/2$，代入后分母正好是 $\sigma^2$。

两式相除、取对数，指数部分相减：

$$\mathrm{LLR}=\frac{(y_I+d)^2-(y_I-d)^2}{\sigma^2}=\frac{4d\,y_I}{\sigma^2}$$

**这就是代码里那一行**：

$$\mathrm{LLR}(b_0)=\frac{4d\cdot y_I}{\sigma^2},\qquad \mathrm{LLR}(b_1)=\frac{4d\cdot y_Q}{\sigma^2}$$

**"max-log"的来历**：严格算法要对多个星座点做 log-sum-exp，计算量大。工程上只保留最大项，误差约 0.5 dB，速度却快很多。这就是 **max-log-MAP**。

### 2.4 代入数字：LLR 长什么样

取 $d=0.707$、$\sigma^2=0.02$，则系数 $\frac{4\times0.707}{0.02}=141.4$：

| 收到的 $y_I$ | LLR $=141.4\,y_I$ | 含义 |
|---|---|---|
| $+0.80$ | $+113$ | 非常确定是 0 |
| $+0.30$ | $+42$ | 确定是 0 |
| $+0.05$ | $+7.1$ | 倾向 0，但不太确定 |
| $0$ | $0$ | **完全不知道** |
| $-0.05$ | $-7.1$ | 倾向 1，但不太确定 |
| $-0.30$ | $-42$ | 确定是 1 |
| $-0.80$ | $-113$ | 非常确定是 1 |

**这个实数就是 LDPC 迭代译码的"原始证据"。**

## 三、软判决 vs 硬判决

### 3.1 区别

| | 硬判决 | 软判决 |
|---|---|---|
| 输出 | `0` 或 `1` | 一个实数（LLR） |
| 信息量 | **1 bit** | 连续值，承载"确信度" |
| 类比 | 法官只判"有罪/无罪" | 法官说"有罪，8 成把握" |

**作者的猜测是正确的**：硬判决只有 0 和 1，软判决是不同数值。

### 3.2 为什么软判决能救回硬判决救不了的错误

**场景**：一个比特发的是 0，但噪声把它推到了负侧，$y_I = -0.05$。

- **硬判决**：判成 `1`，**错定了**
- **软判决**：给出 $\mathrm{LLR} = -7.1$，微弱地倾向 1

**LDPC 看到 $-7.1$ 后做这件事**：

> "我旁边 5 个比特都强烈指向 0（LLR > +40），而这个只弱弱地指向 1（−7.1）。按校验方程它应该是 0。看来是噪声推偏了——**改判成 0**。"

**若只有硬判决**，LDPC 看到"5 个 0 和 1 个 1"，只知道冲突，**不知道哪个更可信，改不过来**。

### 3.3 代价与收益

> **软判决相比硬判决，在 AWGN 信道上通常有约 2 dB 的编码增益。**

2 dB 意味着：同样误码率下发射功率可少 40%，或同样功率下距离可多 25%。

**因此几乎所有现代系统都用软判决。**

### 3.4 在你的系统里的位置

```
射频 → OFDM 解调 → 均衡（ZF）→ 【max-log-MAP 软解映射】→ LLR
                                        ↑ 软信息在这里产生
→ 解交织（LLR 一起搬）→ 软解扰 → 【LDPC BP 译码（吃 LLR）】
→ 硬判决输出比特 → RS 译码（吃字节）
```

**两个要点**：

1. **解交织必须搬 LLR，不能搬比特**（否则软信息丢失）
2. **RS 吃的是字节**，所以 LDPC 输出时必须转成硬判决

**这也是"先 LDPC 后 RS"的原因——顺序不能反。**

## 四、重要修正：7 分钟这个估算被实测推翻

### 4.1 作者的实测观察

> "持续运行数十小时都不会有大问题，最多有间隔几秒的花屏然后恢复。"

**这句话否定了此前的 p 假设。**

### 4.2 重新计算（单位：字节错误率）

约定：$p$ = 字节错误率；锚点 2 字节，被破坏概率 $\approx 2p$。

每秒 150 个包（150,000 字节 ÷ 1000 字节/包）：

$$\text{锚点破坏间隔}=\frac{1}{2p\times150}=\frac{1}{300p}\ \text{秒}$$

| $p$（字节错误率） | 锚点破坏间隔 | 与观察是否相符 |
|---|---|---|
| $10^{-4}$ | **33 秒** | ❌ 太频繁 |
| $10^{-5}$ | 5.5 分钟 | ❌ 太频繁 |
| $10^{-6}$ | 55 分钟 | ❌ 仍太频繁 |
| $10^{-7}$ | 9.3 小时 | ⚠️ 勉强 |
| **$10^{-8}$** | **93 小时** | ✅ 相符 |
| $10^{-9}$ | 39 天 | ✅ |
| $10^{-10}$ | 约 1 年 | ✅ |

**结论：系统真实 $p$ 约在 $10^{-8}$ 或更低**，而非此前假设的 $10^{-6}$。

### 4.3 这个修正的三个后果

#### 后果 1：原论文"残余 BER < 5×10⁻¹⁰"的结论，数值方向可能是对的，但证据无效

- **结论**（残余极稀疏）→ 作者的观察**支持**它
- **证据**（10⁶ 码字零纠正）→ **无效**，因为计数器从未工作

**这两件事必须分开陈述**：不能因为证据有缺陷就否认观察，也不能用观察冒充测量。

#### 后果 2："间隔几秒花屏然后恢复"更可能是别的原因

| 可能原因 | 特征 | 是否匹配"几秒后恢复" |
|---|---|---|
| LDPC 块失败（一个 126 字节块全丢） | 丢一帧，等到下个 I 帧恢复 | ✅ 匹配（GOP 1.5 s） |
| 锚点被破坏导致失步 | 持续错位，直到解码器碰巧找到起始码 | ✅ 也可能 |
| 发送端队列 `try_push` 丢帧 | 丢整帧，GOP 级恢复 | ✅ 匹配 |
| CPU 抢占 / 调度抖动 | 短暂卡顿 | ✅ 匹配 |

**注意：这四种在现象上无法区分。** 这正是实验设计必须解决的第一个问题——**光看画面，分不出是哪种失效**。

#### 后果 3（最关键）：自然误码在 5 分钟内可能一次都不发生

若 $p \approx 10^{-8}$：

| 在 5 分钟（300 秒）内 | 期望次数 |
|---|---|
| 锚点被破坏 | $2\times10^{-8}\times150\times300=9\times10^{-4}$（万分之九） |
| 单个 1024 字节块出现字节错误 | $1024\times10^{-8}\times(150000\times300/1024)\approx0.045$ |

**这意味着 M1 与 M3 在 5 分钟内都"看起来完全正常"，组间无可见差异。**

## 五、这直接改变一周实验的设计

### 5.1 分组有效性

在当前链路条件下（高 SNR，$p\approx10^{-8}$）：

| 组 | 是否有效 | 原因 |
|---|---|---|
| **M0 vs M1** | ✅ 有效 | 差异是结构性的，与 p 无关 |
| **M1 vs M2b vs M3** | ❌ **无效** | 5 分钟内无差异，做不出结论 |

### 5.2 三个应对选项

| 选项 | 做法 | 代价 |
|---|---|---|
| **A（必选）** | **强行压低 SNR**，把 $p$ 提到 $10^{-4}$–$10^{-3}$，使锚点每 30 秒–5 分钟坏一次 | 结果在"低 SNR 工况"下成立，须在论文中声明边界 |
| B（补充） | 只做**人为翻转比特**，不做自然误码对比 | 因果清楚但"人工"，可能被质疑代表性 |
| C（不可行） | 观测时长拉到 5 小时以上 | 设备只有一周 |

**结论：A 是必选，B 是补充。**

### 5.3 D1 的任务因此变成唯一目标

**把 $p$ 调到 $10^{-4}$ 量级。**

| 需要 | 理由 |
|---|---|
| 可调衰减能力 | 固定 30 dB 一步太大，须用 `tx_gain` 扫点 |
| **仪器确认 p** | 不能靠"看起来花屏了"，必须测出数字 |
| **p 达不到时的 Plan B** | 见下 |

### 5.4 若 p 提不到 $10^{-4}$ 的退路

最坏情况：最多只能到 $10^{-6}$（锚点 55 分钟一坏）。那么：

1. **主实验改为"人为翻转比特"**——受控、可重复、不需等随机事件
2. **自然误码对比**降级为"在最高可及 p 下观察到的趋势"
3. **论文重心从"实测统计"转到"机制 + 受控注入"**

**这不是退步**：Iqbal & Zepernick 2019（IEEE Access）**就是纯注入仿真**，同样发表。**受控注入在方法学上甚至更干净**，因为自变量完全由实验者掌控。

## 六、待确认（会改变 D1 计划）

**问题**：作者所说的"间隔几秒花屏然后恢复"，大致多久一次？

| 若 | 推断 | 对 D1 的影响 |
|---|---|---|
| 几小时一次 | $p\sim10^{-9}$ | **必须靠衰减** |
| 几分钟一次 | $p\sim10^{-6}$ | 可用自然误码做实验，衰减为辅 |
| 一小时十几次 | $p$ 更高，或有其他失效源 | 先排查失效源（队列丢帧/CPU） |

**这个答案直接决定 D1 是否需要死磕衰减。**

## 七、这一轮新增的概念

| 术语 | 英文 | 含义 |
|---|---|---|
| 软解映射 | soft demapping | 从接收符号生成 LLR 的过程 |
| 硬判决 | hard decision | 只输出 0/1 |
| 软判决 | soft decision | 输出 LLR（含确信度） |
| 对数似然比 | LLR（Log-Likelihood Ratio） | $\ln\frac{P(0\mid y)}{P(1\mid y)}$ |
| max-log 近似 | max-log approximation | 用最大值代替 log-sum-exp，损失约 0.5 dB |
| 编码增益 | coding gain | 软判决相对硬判决的信噪比优势（约 2 dB） |
| 星座归一化因子 | constellation normalization factor $d$ | 使平均功率为 1，QPSK 的 $d=1/\sqrt2$ |
