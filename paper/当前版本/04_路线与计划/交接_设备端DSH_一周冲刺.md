## 0　一句话任务

> 在强内码 OFDM-ISAC 链路上，用**四种分帧模式 × RS 开/关**的消融实验，证明**实时视频的失效边界在分帧元数据完整性，而不在纠错强度**。

---

## 1　背景：为什么做这个

研究初期按常规思路在 LDPC 内码外搭建 RS 外码，试图降低残余误码。后续代码级复核发现该 RS 实现存在三处缺陷、从未真正工作：

1. 码表初始化被函数级 `static` 标志门控（第 2 个实例起码表全零）
2. 伴随式多项式取向与编码器相反
3. 纠错计数器声明未使用

由此撤回四组结论：稳态零失败、残余 BER<5×10⁻¹⁰、8.4% 吞吐增益、外码仅为瞬态保护。

**但留下一个关键观察**：不加入该模块时，实时视频在第一帧即冻结。这一现象无法用随机误码解释（见 §3），因此研究视角从"纠错要多强"转为"保护该加在哪一层"。

## 2　已在代码中确认的事实（可直接引用）

| # | 事实 | 证据位置 |
|---|---|---|
| 1 | RS 实现有三处缺陷，编解码器从未成功工作 | `include/ReedSolomon.hpp` |
| 2 | 2 字节长度前缀位于 RS 码字内部，接收端用它切分 UDP 载荷 | 调制 `_encode_and_enqueue_payload()`；解调 `rs_decoded[0..1]` |

## 3　关键算术：首帧冻结不可能是随机误码

若残余字节错误率为 $p$，2 字节锚点（16 bit）被破坏的概率约 $16p$：

| p | 首帧撞上错误的概率 | 100 包/s 下平均间隔 |
|---|---|---|
| $10^{-6}$ | $1.6\times10^{-5}$ | 约 10 分钟 |
| $10^{-4}$ | $1.6\times10^{-3}$ | 约 6 秒 |
| $10^{-3}$ | $1.6\times10^{-2}$ | 约 0.6 秒 |
| $3\times10^{-2}$ | ≈40% | 才可能"第一帧就中" |

**结论**：要让首帧必冻结，$p$ 需 >3%，与"链路偏稳态"矛盾。故首帧冻结**只能是结构性的**——定长块链路上缺少边界约定所致，与 $p$ 无关。

由此得到**两种性质不同的失效模式**，这是本文的理论骨架：

| | 模式 A：约定缺失 | 模式 B：锚点失守 |
|---|---|---|
| 触发 | 变长载荷 + 定长块 + 无边界元数据 | 有锚点但被误码破坏 |
| 性质 | **确定性**，首包必失败 | **随机性**，与 p 成正比 |
| 概率 | 1 | $\approx 16p$ |
| 修复 | 建立锚点 | 保护锚点（校验/定长化） |

## 4　四种分帧模式（本实验的核心设计）

```
M0 无锚点   : [payload]                       接收端无法定界
M1 裸前缀   : [2B 大端 len][payload]          按 len 切分
M2 前缀+CRC : [2B len][2B CRC16(len)][payload]  CRC 失败则丢弃该块（不盲目切分）
M3 定长分片 : [2B seq][1022B 字节流]           无需 len，块长由配置固定
```

**设计要点**

- M2 的作用是把"全局错位"降级为"局部丢一块"
- M3 丢弃 UDP 报文边界，把视频当**连续字节流**处理（H.264 Annex B 本身自定界，可行）
- **四组必须同码率、同分辨率、同 GOP、同位置、同天线朝向**

**必须实现的埋点**

| 计数器 | 含义 | 用途 |
|---|---|---|
| `blocks_total` | 收到块数 | 分母 |
| `framing_drop` | CRC 拒绝 / 长度非法 | M2 因变量 |
| `seq_gap` | 序号缺口数 | M3 因变量 |
| `misalign_events` | **连续 3 块内找不到 `00 00 00 01`** | **M0/M1 因变量，最关键** |
| `bytes_delivered` | 实际投递给解码器的字节数 | 排除"少投递"解释 |

## 5　衰减方案：不要买器件，用 tx_gain

设备端可能只有**固定 30 dB 衰减器**（Mini-Circuits VAT-30+），一步 30 dB 太大，找不到落点。

**改用软件 tx_gain 当可调衰减**：X310 发射增益通常 0–31.5 dB、0.5 dB 步进。

**D1 必做：tx_gain 扫点找 p**

| tx_gain | 相对衰减 | 实测 p | 是否可用 |
|---|---|---|---|
| 31.5 | 0 dB | | |
| 25 | ~6 dB | | |
| 20 | ~11 dB | | |
| 15 | ~16 dB | | |
| 10 | ~21 dB | | |
| 0 | ~31.5 dB | | |
| 0 + 30dB 固定 | ~61 dB | | 可能直接挂 |

**判据**：找到 $p$ 落在 $10^{-4}$–$10^{-3}$ 的那一档，即为所有消融实验的工作点。
**这一步不做，后面全白做**——若 p 太低，M1 组 5 分钟一次都不会失步，实验无梯度。

## 7　判定标准（跑之前写死，不许事后改）

| 指标 | 定义 | 阈值 |
|---|---|---|
| 业务可用率 SAR | 可用帧/总帧 × 100%，可用 = **VMAF ≥ 80**（或 PSNR ≥ 30 dB，二选一） | — |
| 流级失步 $N_{\text{mis}}$ | 连续 3 块无起始码，记一次 | — |
| 恢复时间 $T_{\text{rec}}$ | 失步到重新出画的中位数 | — |
| 时延漂移率 $D$ | 线性回归斜率 [ms/min] | $\|D\|<1$ 视为无累积 |
| p | LDPC 译码输出处字节错误率，PRBS 逐字节比对 | 样本 ≥10⁶ 字节/点，给 95% 区间 |

**核心判据（记住这两条）**

- **M0 失败率 ≈ 100%，且不随 p 变化** → 证明"约定缺失是确定性的"
- **M3(RS关) ≈ M1(RS开)** → 证明"分帧完整性可替代外码纠错"

## 9　技术风险与预案

| 风险 | 概率 | 预案 |
|---|---|---|
| **p 太低，M1 组从不失步** | **高** | 用 tx_gain / 固定 30 dB 压到 $10^{-4}$–$10^{-3}$；若仍不够，串联两个 30 dB |

| 设备提前收回 | 中 | 按 §6 的 3 天方案砍 |
