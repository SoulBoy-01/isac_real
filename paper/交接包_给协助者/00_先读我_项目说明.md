## 一、30 秒了解这个项目

**一句话**：在一条"通感一体化"（ISAC）无线链路上传实时视频，研究**视频为什么会卡、卡在哪一层**。

**背景**：6G 想让同一套硬件、同一段频谱既传数据又做雷达感知，这叫 ISAC。开源平台 OpenISAC 让它能在实验室跑起来。但"能传视频"和"视频能稳定用"是两件事——本项目研究后者。

**实验平台**：
- 两台 USRP X310 软件无线电（一发一收），各配铷原子钟
- OFDM 波形，1024 点 FFT，50 MHz 采样，3.1 GHz 载波
- 室内视距链路，约 5 米
- 视频：摄像头 → H.264 编码 → UDP → ISAC 调制 → 空口 → 解调 → 解码 → 显示

**关键约束**：设备**下周（10 月底）之后就要归还**，之后只能靠仿真和已有数据。

## 二、核心发现（一句话版）

> **视频能不能用，取决于"包边界信息放在哪"，而不取决于"纠错码有多强"。**

展开说：

发视频时，连续的字节流必须切成一个个包才能上网。切包就要告诉接收端"这一包到哪结束"。有三种标法：

| 方法 | 边界信息放在哪 | 会被误码破坏吗 |
|---|---|---|
| 定长（如每包 1024 字节） | **配置里** | **不会** |
| 长度前缀（如前 2 字节写长度） | **数据里** | **会** |
| 分隔符（如找特殊标记） | **数据里** | 会（会认错） |

**现在的系统用的是"长度前缀"**——这 2 字节一旦被误码改了，接收端就从这里开始切错，而且**此后每一包都错位**（因为每次解析都依赖上一次的结果）。这叫**失步**。

**本项目的方案**是把载荷改成**定长分片**（每块固定 1024 字节，2 字节序号 + 1022 字节数据），边界由"这是第几块"直接算出，**误码改不了**，所以**永不失步**。

## 三、⚠️ 重要：已经撤回的内容（千万不要引用）

这是最需要你知道的部分，**避免帮倒忙**。

研究早期，作者在平台上加过一层 Reed-Solomon（RS）纠错码，并据此得出过几个结论。**后来代码级复核发现，那个 RS 实现有三处缺陷，从未真正工作过**：

1. 码表初始化被函数级 `static` 标志门控 → 第 2 个实例起码表全零
2. 伴随式多项式取向与编码器相反
3. 纠错计数器从未累加

**因此以下结论全部作废，任何材料里出现都视为错误**：

| ❌ 已撤回 | 原因 |
|---|---|
| "四种 RS 配置稳态零失败" | 解码器从未真正纠错，也从不报错 |
| "残余误码率 < 5×10⁻¹⁰" | 由上一个观察推出，不成立 |
| "换用 RS(255,223) 回收 8.4% 吞吐" | 按码率比推算，未经实测，且依赖无效实现 |
| "外码在稳态只是瞬态保护" | 同上 |

**如果看到旧的论文稿（`manuscript_conference_v2.docx`、`manuscript_sci_v1.md`）里有这些说法，那是旧版本，已废弃。**

**但这不代表工作白做**——正是这次"发现自己的测量链有缺陷"，直接催生了现在的主线（因为作者发现：不加这个 RS 模块，视频第一帧就冻结；而 RS 从没纠过错，所以真正起作用的是那 2 字节前缀，也就是**分帧**）。

## 八、术语速查

| 术语 | 含义 |
|---|---|
| **ISAC** | 通感一体化，通信与雷达感知共享同一波形 |
| **OFDM** | 正交频分复用，一种多载波调制方式 |
| **LDPC** | 一种强纠错码（低密度奇偶校验码），本项目内码 |
| **RS 码** | 另一种纠错码（里德-所罗门），本项目外码（已发现实现缺陷） |
| **p** | LDPC 译码后、RS 译码前的**字节错误率**（全项目统一用字节错误率） |
| **M0/M1/M2a/M2b/M3** | 五种分帧方式：无边界 / 裸前缀 / 前缀+CRC丢弃 / 前缀+CRC重同步 / 定长分片 |
| **失步** | desynchronization，接收端对边界的判断与发送端不一致，且错误沿包序列累积 |
| **GOP** | 图像组，H.264 中一个 I 帧到下一个 I 帧的间隔（本项目 30 帧 = 1.5 秒） |
| **I/P 帧** | 帧内编码帧 / 前向预测帧（P 帧参考前面的帧，所以错误会传播） |
| **γ** | 容器放大因子，衡量"一个物理误码被放大了多少倍" |
| **VMAF** | 视频质量客观评分（本项目拟用，阈值暂定 80） |

见第三节。旧稿（`manuscript_*`）里的 8.4%、5×10⁻¹⁰ 全部作废。

**② 不要声称"平台是作者开发的"**

**③ 不要假设"改了代码就等于好了"**

这个项目最大的教训是：**看起来能跑，不等于实现正确**。任何改动都要有单元测试或对照实验。
